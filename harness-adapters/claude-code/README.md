# Claude Code adapter

Claude Code discovers instructions from a few conventional locations in
a project or in `~/.claude/`. The two that matter here are
`.claude/agents/*.md` — subagents, each a markdown file with `name`,
`description`, and `tools` frontmatter, dispatched when its description
matches the task — and `.claude/skills/*/SKILL.md`, directories loaded
on demand by name. A `.claude-plugin/plugin.json` manifest bundles a
set of these for distribution, which is why this repo carries one at
its root.

Which tier a pointer resolves to is decided at generation time by
`ai_agents.tiers.resolve`, so a project that has installed its own copy
of an agent gets a pointer into `.ai-agents/`, and everything else
points at the user master.

## Generated artifact

One file per installed agent, at `.claude/agents/<agent-name>.md`,
relative to the directory Claude Code runs in — the project root for
the project and workspace tiers, `~/.claude/agents/` for the user
tier. The file is markdown with YAML frontmatter. The frontmatter is
what Claude Code reads to decide whether to dispatch to this agent, so
`name` and `description` must be present and accurate; the body is
just the pointer.

## Template

```
---
name: {agent_name}
description: {agent_description}
---

<!-- Generated by ai-agents. Do not hand-edit this file — edit
     {agent_path} instead and reinstall. -->

Skills: {skill_list}
Workflows: {workflow_list}

Full instructions and boundaries for this agent are at:

{agent_path}

Resolved tier: {tier}.
```

Skills and Workflows are separate kinds — one atomic and individually
invocable, one cumulative and composed of Skills (see
`ARCHITECTURE.md`, "Skills and Workflows") — so the pointer carries
both lists rather than collapsing them into one. When a kind is empty,
its line is omitted entirely rather than kept as a dangling label with
nothing after the colon: `stock-screening` has Skills but no
Workflows, so its pointer gets a `Skills:` line and no `Workflows:`
line at all. Only when an agent has neither kind does the pointer fall
back to a single `(none)` line in place of both. This rendering
convention matches `cli.list_cmd` exactly, so a change to one should
prompt a change to the other.

## Multi-agent behavior

Multiple installed agents mean multiple files — one
`.claude/agents/<agent-name>.md` per agent, each independent of the
others. There is no combined block and no ordering concern, since
Claude Code dispatches per file on `description` match rather than
reading them as one document.

## Verification

This format is derived from the discovery mechanism described above —
frontmatter-driven subagent dispatch under `.claude/agents/*.md` — and
not from a live install of Claude Code against a generated pointer.
Unverified against a live install.
